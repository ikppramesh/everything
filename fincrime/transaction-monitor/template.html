How It Works

From Transaction to STR in Four Steps

The dashboard simulates the complete detection-to-reporting pipeline used by financial intelligence units.

1

Transaction Generated

A new transaction is synthesised every 0.8–2.5 seconds using realistic Indian account data across multiple channels.

2

Rules Evaluated

All enabled AML rules are checked against the transaction and historical data. Rule fires set risk level to High.

3

Alert Created

A new alert card is prepended to the queue with rule context, account details, and analyst action buttons.

4

STR Filed

Analyst reviews, escalates if needed, then files an STR — generating a unique STR-2026-XXXXX reference number.

AML Rule Engine

Six Detection Rules, Fully Configurable

Each rule can be toggled on or off and its threshold adjusted in real time from the dashboard's built-in rule panel.

🏭

Structuring Rule

Multiple transactions just below ₹10 lakh threshold within 24 hours from the same account — a classic layering technique.

Threshold: ₹9,00,000
⚡

Velocity Rule

More than 5 transactions from the same account within any rolling 10-minute window — indicative of automated fund movement.

Max: 5 txns / 10 min
🌎

Geography Rule

Transaction involving a high-risk jurisdiction — identified by the HRJ- account prefix — above the configured amount threshold.

Threshold: ₹5,00,000
🔄

Round-Trip Rule

Funds return to the originator account within 2 hours of being sent — a strong indicator of circular fund movement.

Threshold: ₹2,00,000
😴

Dormant Account Rule

First transaction after 12+ months of inactivity that exceeds the threshold — a common money mule activation pattern.

Threshold: ₹10,00,000
🏥

Mule Account Rule

Account balance near zero before and after a rapid large transaction — characteristic of pass-through mule account behaviour.

Threshold: ₹5,00,000
